## Design

1. `packages/utils/src/run-lane.ts`: add `export type RunLane = "review" | "pr" | "task"` and `export function resolveRunLane(input: { prKey?: string; supersedePolicy?: string; prNumber?: number }): RunLane`, the same body and doc comment as the worker's. Optionally express `resolveRunDisplayLane`'s non-self-heal tail through it (same result).
2. `packages/worker/src/agent-run/run-lane.ts`: delete the local `RunLane`/`resolveRunLane` and re-export both from `@terragon/utils/run-lane`. No worker call site changes. Keep `ownsAbnormalTerminal` and `formatRunStartLine` as they are.
3. `apps/www/src/agent/hatchet/dispatch.ts`: in the `cellMarker` condition, add `resolveRunLane({ ...baseInput, ...plan?.inputExtension, ...taskPlan?.extension }) === "task"` (or the equivalent fields), and say in the comment that the worker's `selectRunExecutor` refuses any other lane (#757). It is evaluated before `cellEligibilityAtDispatch`, so a PR run does no eligibility DB reads.
4. Tests:
   - `packages/utils/src/run-lane.test.ts`: a `resolveRunLane` block (prKey → review; supersedePolicy → review; prNumber → pr; none → task; prKey beats prNumber).
   - `apps/www/src/agent/hatchet/dispatch-cell-marker.test.ts`: "a non-review PR thread (#757) never gets the marker". An org thread with `githubPRNumber` set and no review automation (a merge-audit or PR-mention shape) gets no `cell`, while `dispatchPlain({ organizationId: orgId })` in the same test still gets `cell: "opensandbox"`.
   - AC-4 parity: a test in the worker (`run-executor.test.ts` or a new small test) that runs `selectRunExecutor` on the input shapes www marks (no PR, no prKey, no selfHeal, no reviewAgent) and accepts them, and refuses a `prNumber` one. That pins both sides to the one shared function.

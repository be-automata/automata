### Behaviour (OpenSandbox shapes from spike 058 `run.mjs` and upstream `specs/sandbox-lifecycle.yml` @ `db708c21`)

- **`create(plan)`**:
  1. Refuse **before any HTTP call** with `CellProviderError("runtime_not_runc")` when `plan.runtime !== "runc"`, and with `CellProviderError("policy_required")` when `plan.networkPolicy` is missing, its `defaultAction !== "deny"`, or its `egress` is not an array (AC-2; the type says it is always there, but callers can be untyped).
     Also refuse before any HTTP call with `CellProviderError("ttl_too_short")` when `Math.ceil(plan.ttlMs / 1000) < 60` (server minimum, upstream `sandbox-lifecycle.yml:2286-2290`).
  2. `POST /sandboxes` with exactly `{ image: { uri: config.image }, entrypoint, timeout: Math.ceil(plan.ttlMs / 1000), resourceLimits: { cpu: <millicores>, memory: <memoryMiB>Mi }, metadata: plan.tags, networkPolicy: plan.networkPolicy, credentialProxy: { enabled: true } }`, where cpu is `Math.max(1, Math.round(plan.resources.cpu * 1000))` millicores with an `m` suffix (AC-1: `networkPolicy` is the plan's object, deep-equal). Expect 202 (spike 058 `claude.create_202`) or 2xx; a 2xx without `id` falls back to list-and-adopt. **Not blindly retried**: a 502 whose body code is `BACKEND_CONNECTION_FAILED` is retried (undelivered, see Retries). Any other 5xx, a transport failure or an unusable 2xx may mean the server created the cell, so the adapter lists by the plan's full identity (below), repeating the list within `retryBudgetMs` while it finds nothing: exactly one match is adopted (after its policy is read back and verified), more than one is revoked, quarantined and deleted and `create` throws `http_error`, none after the budget logs one warning and throws `http_error`. The reconciler (S4) is the backstop for a cell whose create landed later (it carries `expiresAt`).
     From the moment an id is known, every later step runs inside try/catch that tears the cell down before rethrowing.
  3. Wait until execd answers `GET /sandboxes/{id}/proxy/{execdPort}/ping` with 2xx, polling via `deps.sleep(100)`, bounded by `readyTimeoutMs` on `deps.now()`. A fetch rejection or a non-2xx counts as "not yet" (spike 058 `run.mjs:93`). On timeout: tear down and throw `CellProviderError("not_ready")`.
  4. **Self-check (AC-4), fail closed**: `exec(id, config.selfCheck.argv)`. The probe contract: the probe makes a **TLS + HTTP request** to a host the policy denies (a bare TCP connect proves nothing under the sidecar's MITM, spike 058 README:83) and exits **`3` when blocked** (NXDOMAIN, refused or timed out), **`0` when it got a response**. Exit `3` → enforced, continue. **Anything else** — exit 0, any other exit code, an execd `error` event, a non-2xx from `/command`, a stream with no `execution_complete`, a timeout — tears the cell down and throws `CellProviderError("egress_not_enforced")`. Runs **before** the vault is written, so no secret ever enters an unproven cell. The exit code `3` is exported as `OPENSANDBOX_SELF_CHECK_BLOCKED_EXIT`.
  5. `POST /sandboxes/{id}/credential-vault` (create-only, a retry can 409: retried **only** on a 502 with body code `BACKEND_CONNECTION_FAILED`) with `{ credentials: vault.map(v => ({ name: v.name, source: { type: "inline", value: v.credential } })), bindings: vault.map(v => ({ name: v.name, match: { hosts: [...v.hosts], ...(v.paths ? { paths: [...v.paths] } : {}) }, auth: { type: v.auth, credential: v.name } })) }` (spike 058 `run.mjs:239-247,424-426`; 201 expected). A failure here tears the cell down and throws `http_error`.
  6. Return `{ cellId: id }`.
- **`exec(cellId, argv, opts?)`**: an empty `argv` or an empty `argv[0]` throws `CellProviderError("invalid_argv")` before any HTTP call (execd requires `minItems: 1`). The request's signal is `AbortSignal.timeout((opts?.timeoutMs ?? 120_000) + 10_000)` and covers the SSE body read; `requestTimeoutMs` applies to control calls only. `POST /sandboxes/{id}/proxy/{execdPort}/command` with `{ argv: [...argv], timeout: opts?.timeoutMs ?? 120_000, ...(opts?.cwd ? { cwd: opts.cwd } : {}) }` — execd's native `argv` (upstream `execd-api.yaml:2620-2680`, `RunCommandRequest`), not a hand-rolled shell quote (adopt over build; spike 058 only used `command`, so S3 proves `argv` live). Parse the SSE body (`data: {json}` lines; `stdout`/`stderr` text appended, read under `maxExecOutputBytes`). Exit codes follow the upstream execd schema (`execd-api.yaml:2747`): an `error` event with an integer `error.exit_code` (fallback: top-level `exit_code`) is a completed run with that exit code and wins over a later `execution_complete`; an `error` event with no integer exit code fails the run (`http_error`); an `execution_complete` with `exit_code: 0` is success, and one with a missing or non-integer `exit_code` is malformed (`http_error`), because absence does not imply success. A non-2xx throws `http_error`; a stream with no terminal event throws `http_error`. `create` also refuses (`invalid_plan`, no HTTP call) a plan with a blank worker/epoch/stepKey/attempt/expiresAt tag, `tags.automata !== "cell"`, or a non-positive or non-finite cpu/memoryMiB. Retried **only** on a 502 whose body code is `BACKEND_CONNECTION_FAILED` (see Retries); any other 502 can come after delivery and is never retried (upstream `server/opensandbox_server/api/proxy.py:505-540` @ `db708c21`). Secrets are never passed here (execd logs commands; ticket Contract › Credentials).
  - **S1 type change in this PR**: `stdin` is removed from `CellExecOptions` (execd has none); `CellVaultAuth` becomes `"bearer"` only (OpenSandbox `apiKey` needs a header name the type does not carry, `sandbox-lifecycle.yml:2929-2960`; S1's builder emits only `bearer`). `packages/types/src/cell.ts` joins P1 (4 files).
- **`copyOut(cellId, path)`**: `GET /sandboxes/{id}/proxy/{execdPort}/files/download?path=<encoded>` → bytes; a non-2xx throws `http_error` (never returns an error body as bytes). No live evidence yet (spike 058 never called it): S3 covers it.
- **`revoke(cellId)`**: `DELETE /sandboxes/{id}/credential-vault`; a 404 is a no-op (the cell or its vault is already gone).
- **`quarantine(cellId)`**: `PUT /sandboxes/{id}/networkpolicy?dropEstablished=true` with `{ defaultAction: "deny", egress: [] }`; a 404 is a no-op; any other non-2xx (e.g. the sidecar's `DropEstablishedNotImplemented`, upstream `egress-api.yaml:424`) throws `http_error`.
- **`delete(cellId)`**: `DELETE /sandboxes/{id}` → `"deleted"` on 2xx (204), `"gone"` on 404.
- **Teardown inside create** (self-check, readiness or vault failure): `revoke` → `quarantine` → `delete`, always in that order and all best-effort (a failure is logged without secrets and the original error is thrown). `revoke` always runs first because an adopted cell's vault state is unknown (an earlier delivery may have written it); a 404 makes it a no-op for a cell whose vault was never written.
- **`listByTags(tags)`**: always filters `automata=cell` plus the given tags (`{}` never lists every sandbox): `GET /sandboxes?metadata=<encodeURIComponent(new URLSearchParams({ automata: "cell", ...tags }).toString())>&page=N&pageSize=100` — each key and value encoded first, then the whole string (the server parses with `strict_parsing`, upstream `sandbox-lifecycle.yml:612-617`) (server-side filter, spike 058 `recon.metadata_filter_server_side`), following `pagination.hasNextPage`; returns `{ cellId: item.id, tags: item.metadata ?? {} }[]`.
- **Retries** (backoff `deps.sleep(250 * 2^n)` capped at 2 s, until `retryBudgetMs` on `deps.now()` is spent; ticket Contract › Teardown: "A 502 is retried"; spike 058 README:81 saw 502s on `/command` and the vault for a few seconds after ping):
  - **idempotent** calls — `GET` (ping excluded: it has its own loop), `PUT …/networkpolicy`, `DELETE` — retry any 502;
  - **non-idempotent** POSTs — `/sandboxes`, `…/command`, `…/credential-vault` — retry a 502 **only** when the JSON body's `code` is `BACKEND_CONNECTION_FAILED` (the server proxy never reached the backend, so nothing was delivered; upstream `proxy.py:505-540`, body flattened to `{code, message}` in `main.py:309-318`). The body is parsed for `code` only and never logged or put in an error. `BACKEND_RESPONSE_FAILED` or an unrecognised body is not retried.
- **Errors**: `CellProviderError` with `code: "runtime_not_runc" | "policy_required" | "ttl_too_short" | "invalid_argv" | "not_ready" | "egress_not_enforced" | "http_error"`, `status?: number`, and `op` (`"create" | "vault" | …`). The message is `${op}: ${code}${status ? " " + status : ""}` — never a response body, never a header.
- The adapter never orders revoke before the control plane's `revokeAttempt` (that cross-plane order is S4/S5); it only exposes the provider steps.

- **Deprecated path, recorded**: `/sandboxes/{id}/proxy/{port}` is in upstream maintenance mode (`server/configuration.md:78` @ `db708c21`), with `/endpoints/{port}` as the successor; it works and the server injects execd's own token. Kept for 1.2.1 because spike 058 proved it; moving is a follow-up.

## Exec exit codes and adopted-cell policy (roborev 1164, findings 1, 2, 4)

Upstream execd schema (data): `exit_code` on an `execution_complete` event is "Successful foreground POST /command process exit status (0) ... Absence does not imply success; older servers omit this field. Non-zero command exits use error.exit_code instead." The `error` event carries `error: { ename, evalue, traceback?, exit_code? }`; older servers put `exit_code` at the top level (spike 058's parser read `e.error?.exit_code ?? e.exit_code`).

- **1**: an `error` event whose `error.exit_code` (else top-level `exit_code`) is a finite integer is a completed run with that code, not a failure. An `error` event without one is a failed run (`undefined`, so `exec` throws `http_error`). The self-check: exit 3 (even via an error event) = blocked, continue; exit 0 = reached, teardown; any other code or a failed run = teardown, `egress_not_enforced`. Replaces the test "an error event even carrying exit 3" (which asserted failure) and "an error event with exit 0" (which asserted `http_error`).
- **2**: an `execution_complete` with a missing or non-integer `exit_code`, and no earlier or later numeric-exit error event, is malformed: `undefined`, so `http_error`. `exit_code: 0` gives `exitCode` 0. If both a numeric-exit error event and an `execution_complete` arrive, the error event's code wins. Replaces the test "defaults a missing exit_code to 0".
- **4**: after list-and-adopt adopts one cell (any ambiguous create), `GET /sandboxes/{id}/networkpolicy` (idempotent retry rules) must show `mode === "enforcing"` (any other or missing mode is a mismatch; spike 058's real GET returned `enforcing`), `policy.defaultAction === "deny"`, and `policy.egress` equal to `plan.networkPolicy.egress` as an unordered multiset, each rule normalised to `{action, target: target || undefined, ports: sorted ports or undefined}`. Response shape (spike 058 `out/enforce-policy.json`): `{"status":"ok","mode":"enforcing","enforcementMode":"dns+nft","policy":{"egress":[{"action":"deny","target":"","ports":[80]},{"action":"allow","target":"httpbin.org"}],"defaultAction":"deny"}}`. On a mismatch, a malformed body or a 404 the cell is torn down (revoke first) and `create` throws `http_error`; the vault is never written. For an adopted cell the order is `waitReady` (ping) first, then this policy check, then the self-check, then the vault: a still-starting cell's policy read can 5xx, so a 5xx or a transport failure of this GET is "not yet" and is retried every 100 ms within `readyTimeoutMs` (counting sleeps, so a frozen clock stays bounded); the budget running out is a mismatch. A 2xx with a mismatching, `deny_all`, non-enforcing or malformed body, or a 404, is an immediate mismatch. A non-adopted create keeps ready, self-check, vault.
- Rule precedence: deny always wins over allow (upstream egress.md:37); spikes 058/068 measured :80 refused with the trailing targetless deny — order is irrelevant.

## Review rules (roborev job 1165)

- **Ambiguous create**: any 5xx from `POST /sandboxes` is an ambiguous create and runs list-and-adopt with its status (adopt-none logs the single secret-free warning and throws `http_error`). The one exception is a 502 with body code `BACKEND_CONNECTION_FAILED`, retried as undelivered. A 4xx is a plain `http_error`: the server rejected it, no cell exists, no list call.
- **Adopted policy**: `verifyAdoptedPolicy` accepts only `mode === "enforcing"`; `observe`, `disabled`, `deny_all` or a missing mode tear the cell down and throw `http_error`, with no vault.
- **Error body cap**: a 502 body is read through `readCappedText` with `MAX_ERROR_BODY_BYTES = 64 * 1024`. Over the cap or unreadable yields no `code` (so not retried as undelivered) and the stream is cancelled.
- **JSON reply caps**: list pages, the adopted cell's policy read-back and the create reply are read through `readCappedJson` (built on `readCappedText`, one cap implementation, then `JSON.parse`). `MAX_LIST_PAGE_BYTES = 1 MiB`, `MAX_POLICY_BODY_BYTES = 64 KiB`, `MAX_CREATE_REPLY_BYTES = 64 KiB`. Over the cap or unparseable cancels the stream and fails with no body content, then takes the existing malformed path: list → `http_error`; policy → mismatch (teardown, no vault); create reply → unusable 2xx, list-and-adopt.

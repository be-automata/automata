# #656 PR-F: the cell guest image

Ticket: be-automata/automata#656 (S5 of #634). This PR is "PR-F" of the 7-PR plan. Branch `feat/656-f-cell-image`, off `main` at `446caab6` (PR-B #665 merged).

It covers:

- Scope item 9, its "Guest image" bullet: a derived **cell image** under `deploy/images/cell/`, FROM the ADR-013 batteries image by digest, with the daemon bundle baked in and an entry that needs no `run.env` and no socket bridges;
- the CI workflow that builds, verifies, publishes and attests it, and prints the digest the box pins;
- the image half of AC-13. AC-13 itself stays DEFERRED until PR-E's live canary scan.

Out of this PR:

- the worker that creates the cell, clones, writes HOME, sends messages and tears down (PR-E);
- the box: the OpenSandbox server, its dedicated rootless daemon, the pre-pull and the server config (PR-G).

## Decisions

1. **Bake the bundle and two small static scripts, nothing per run.**
   - **Why the bundle:** a cell cannot bind-mount, and it has no copy-in (`cell.ts:164-187`).
   - **Why two scripts:** an exec has no stdin (`cell.ts:124-133`) and `--write` reads stdin, so a fixed helper replaces ad-hoc shell quoting in PR-E.
   - **What runs them:** the entry runs as the request `entrypoint` that bootstrap execs (`container_ops.py:488-505`). The image sets no ENTRYPOINT or CMD of its own, because OpenSandbox replaces both.
2. **The image sets nothing about the daemon token.**
   - The daemon takes the token from each message (`shared.ts:19`), not from env.
   - PR-E sends `CELL_DAEMON_TOKEN_PLACEHOLDER` as the message `token`. The daemon then sets `DAEMON_TOKEN=<placeholder>` for the agent child (`daemon.ts:671`), and the vault swaps it on `/api/daemon-event` only.
   - The entry **refuses to start** if any credential-shaped env name is set at all. This is defence in depth: the daemon passes all of `process.env` to the agent (`daemon.ts:668-672`), so a credential in the cell's env would reach Claude and its tools.
   - **The rule:** refuse any name matching `TOKEN|SECRET|PASSWORD|API_KEY|CREDENTIAL` (case-insensitive) or starting with `AWS_`, unless the name is on `CELL_ENV_ALLOWLIST`. It is the same pattern `verify.sh` uses.
   - **`CELL_ENV_ALLOWLIST`, named in full:**
     - set by OpenSandbox: `OPENSANDBOX_ID`, `OPENSANDBOX_EGRESS_MITMPROXY_TRANSPARENT`;
     - set by its bootstrap: `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`;
     - set by this image: `OPENSANDBOX_MERGED_CA_PATH`, `GIT_SSL_CAINFO`;
     - set by the batteries image: the 18 names in Ground truth.

     None of these matches the pattern today. The list exists so that a later rename that does match fails a test and gets a review, instead of silently bricking every cell.
   - **It covers both env channels:** a request `env` (none today) and the operator's `docker.sandbox_env` (`config.py:1411-1415`). A box config that ever puts a credential in `sandbox_env` makes every cell fail closed at start.
3. **The URL is an entry argument.**
   - The adapter sends no create env and exec has none, so PR-E passes `["/opt/automata/cell-entry.sh", "--url", "https://<plan.tags.deployment>"]` as the provider's `entrypoint`.
   - The entry accepts only `https://` + a lowercase host + an optional port, so a stray value can never become a daemon flag.
   - **The entrypoint is fixed per provider, but the host is per run.** `OpenSandboxCellConfig.entrypoint` is fixed when the provider is built (`opensandbox-cell.ts:69-74`, used at `:703`), while `--url` comes from `plan.tags.deployment`. PR-E must either build the provider per deployment host (cached by host; one host per worker in practice) or make the entrypoint per-plan in the adapter. See "Left to PR-E".
4. **TLS for uid 10001 is made to work by config, not by root.**
   - The guest stays non-root, and the server sets `no_new_privileges`, so sudo is not an option either.
   - The image sets `OPENSANDBOX_MERGED_CA_PATH` to a path in the agent's HOME, so bootstrap's merged bundle is writable. Bootstrap then points `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE` at full roots + MITM CA (curl, Python, Go's `gh`), and `NODE_EXTRA_CA_CERTS` covers the daemon and Claude Code.
   - It sets `GIT_SSL_CAINFO` to the same path, because Ubuntu's `git` uses libcurl-gnutls, which ignores `SSL_CERT_FILE`. `verify.sh` checks that linkage.
   - The failed system-store install is a logged warning upstream, and its watcher retries. Accepted.
   - Adopt-over-build: this uses upstream's own knob (`bootstrap.sh:245`) instead of a CA step of ours.
   - **Why a bundle the agent can write is safe:**
     - **Same uid only.** The only writer is uid 10001, the same identity that runs every tool in the cell. Something that can rewrite the bundle can already run arbitrary code as that user, so a write gains it nothing.
     - **The daemon does not trust it.** `NODE_EXTRA_CA_CERTS` points at the MITM CA under `/opt/opensandbox` (`bootstrap.sh:589`, `:621`), which the egress sidecar exports, not at the HOME bundle. Who owns that file in a uid-10001 guest is checked by PR-E's live gate. So the daemon's callback and Claude Code's model calls do not trust the HOME file.
     - **Trust is enforced outside the guest.** All egress goes through the sidecar, which terminates TLS and verifies the upstream certificate itself. A CA planted in the guest bundle could only make the guest trust a server it cannot reach past the sidecar's allowlist. It never weakens the sidecar's own verification.
5. **A Flutter shim dir sits first on `PATH`.** It is `CONTAINER_FLUTTER_SHIM_DIR` (`container-entry.ts:38`, reused, no new constant): `PATH=/home/agent/.automata-run/flutter-pin:<batteries PATH>`. Because an agent-writable dir comes first on PATH, both scripts call node by its absolute path, `/usr/local/bin/node` (`Dockerfile:142-146`), never through PATH. PR-E can then write the pin shims after the clone without restarting the daemon. The box's PATH rewrite (`container-entry.ts:105`) is not needed, because the shims shadow `/opt/flutter/bin`.
6. **A separate package and workflow:** `ghcr.io/be-automata/automata-cell`, built by `.github/workflows/cell-image.yml`. Reasons:
   - The triggers differ: the daemon changes often, the batteries rarely.
   - A cell build must FROM an already published batteries digest, so it can never share a run with a batteries build.
   - The considered alternative was a `cell-sha-…` tag in `automata-batteries`. It avoids the one-time visibility step but mixes two images under one name. Rejected.
7. **The build context is staged.**
   - CI builds the daemon with pnpm and copies `dist/index.js` beside the Dockerfile and scripts in `$RUNNER_TEMP/cell-ctx`. That mirrors how the box stages the bundle (`packages/worker/deploy/README.md:51-58`).
   - No repo-root context, so no `.dockerignore` to maintain. The gitleaks scan covers exactly what enters the image.

### 2. `deploy/images/cell/cell-entry.sh` (new, mode 100755)

```bash
#!/bin/bash
set -euo pipefail
# cell-entry.sh --url https://<broker-host>[:port]
# Run by OpenSandbox's bootstrap as the cell's command (uid 10001). No run.env,
# no socket bridges (#656 Scope 9). Never echoes a value it refuses.
usage() { echo "usage: cell-entry.sh --url https://<host>[:port]" >&2; exit 64; }
[ "$#" -eq 2 ] && [ "$1" = "--url" ] || usage
url="$2"
[[ "$url" =~ ^https://[a-z0-9]([a-z0-9.-]{0,251}[a-z0-9])?(:[0-9]{1,5})?$ ]] || usage
# Names the platform itself sets (CELL_ENV_ALLOWLIST in cell-image.ts; a test
# keeps the two lists equal).
allow=" OPENSANDBOX_ID OPENSANDBOX_EGRESS_MITMPROXY_TRANSPARENT NODE_EXTRA_CA_CERTS REQUESTS_CA_BUNDLE SSL_CERT_FILE OPENSANDBOX_MERGED_CA_PATH GIT_SSL_CAINFO DEBIAN_FRONTEND LANG LC_ALL PUB_CACHE FLUTTER_ROOT FLUTTER_SUPPRESS_ANALYTICS DART_SUPPRESS_ANALYTICS CI PATH SOMNIO_ROOT VENDOR_SKILLS_ROOT CLAUDE_PLUGIN_ROOT YTCTL PLAYWRIGHT_BROWSERS_PATH HOME GSTACK_SESSION_KIND ROBOREV_TELEMETRY_ENABLED MCP_TIMEOUT "
while IFS= read -r name; do
  case "$allow" in *" $name "*) continue ;; esac
  if [[ "${name^^}" =~ TOKEN|SECRET|PASSWORD|API_KEY|CREDENTIAL ]] || [[ "$name" == AWS_* ]]; then
    echo "cell-entry: $name is set; a cell's credentials live in the sidecar vault, never in its env" >&2
    exit 78
  fi
done < <(compgen -e)
run="$HOME/.automata-run"
# 0700 dirs: only uid 10001 reads the socket. The process umask is left as
# inherited: the box's 0002 (container-entry.ts:76) exists for setgid dirs
# shared with the worker on the host, which a cell does not have.
(umask 0077; mkdir -p "$run/flutter-pin")
exec /usr/local/bin/node /opt/automata-daemon/index.js --url "$url" --socket-path "$run/daemon.sock"
```

- **Exit codes:** 64 (EX_USAGE) for bad arguments, 78 (EX_CONFIG) for a forbidden env name. Only the variable **name** is printed, never its value.
- **The umask is scoped to the `mkdir`.** Only the run dir needs to be private. A process-wide 0077 would change the mode of every file the agent writes for no gain, since a cell has one uid. The box's 0002 is not copied either, because its reason (group-writable files in setgid dirs the host worker reads, `container-entry.ts:74-76`) has no counterpart in a cell. The worker reads the cell only through `exec` and `copyOut`, as the same uid.
- **Absolute `node`:** `PATH` starts with an agent-writable dir (Decision 5), so a planted `node` there must never be what the entry execs.
- **No Somnio rules, Flutter pin or git steps here.** They need the checkout, which PR-E clones after the cell is up. PR-E runs them by exec (see "Left to PR-E").

## Risks

- **TLS as uid 10001 is unproven live.** S3 used a root guest. If the merged bundle or `GIT_SSL_CAINFO` does not take, the daemon or the clone fails TLS in the cell. It fails closed (nothing leaks), and PR-E's live gate catches it.
  - **Fallback:** an `EXECD_BOOTSTRAP_PRE_SCRIPT` the image ships that builds the bundle itself (`bootstrap.sh:662-679`).
  - **Never:** root, or a sudo grant.
- **Daemon and worker drift.** The worker runs the daemon protocol of its deploy revision, while the cell carries the bundle of the image's revision.
  - **Mitigations:** the `revision` label; PR-E logs the cell digest per run; the README makes "bump `OPENSANDBOX_GUEST_IMAGE` with each worker deploy" a deploy step.
  - **Future:** a version check at cell start against `DAEMON_VERSION` (`shared.ts:10`) is cheap and can go in PR-E.
- **Ready time.** With the image pre-pulled, bootstrap's CA wait (up to the 15 s stabilisation window) still comes before execd answers, inside the adapter's 60 s budget (`opensandbox-cell.ts:29`).
  - A cold pull of about 8.3 GB exceeds both that budget and the 30 s request timeout (`:31`), so the pre-pull (PR-G) is required, not an optimisation.
- **Box disk.** A second copy of the batteries layers in the OpenSandbox daemon's store (see PR-G). Measure it on the throwaway box first.
- **gitleaks on the bundle.** The minified bundle may trip a rule.
  - **If it does:** a reviewed, path-scoped allowlist entry for `daemon/index.js` with the rule id. Never `--no-verify`, and never dropping the scan.
- **First push of a new package.** It is private until an owner flips it (`README.md:83-88`). The box cannot pull anonymously until then, which is a manual step in the PR description.
- **Rollback:** the image is unused until PR-E reads `OPENSANDBOX_GUEST_IMAGE` on the worker. Reverting means deleting the workflow and the directory. A published digest is inert.
